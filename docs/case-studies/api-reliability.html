Problem

An integration incident is not just a technical error. It can leave an application in an ambiguous state, delay a partner decision, create repeat follow-ups and increase operational workload.

Operational model

Detect → Classify → Assign → Recover → Reconcile → Learn

Each incident should connect a technical event to affected application IDs in a privacy-safe internal workflow, a named owner, customer/partner impact, next action and recovery status.

Recommended controls

  • Define consistent incident categories and severity levels.
  • Track failure rate, retry outcome and time to recovery.
  • Separate transient failures from persistent integration or data-mapping issues.
  • Reconcile application states after recovery to prevent silent stuck cases.
  • Review recurring failures with engineering and partner teams.

Prajakta’s product takeaway

Reliability should be measured by downstream customer and operational impact. An API incident is not just an uptime event. Connecting failure states to stuck applications, recovery time, manual work and customer impact helps teams prioritise fixes that protect the end-to-end lending journey.
