Swiggy: Late-Delivery Friction

An independent product teardown of delivery ETA uncertainty, communication and recovery when an order is late.

View full project on GitHub ↗Print / Save as PDF

Problem framing

When an order is late, uncertainty can feel worse than the delay itself. Users need a credible updated ETA, an explanation when available and a clear recovery path when the order misses expectations.

Journey to examine

  1. Order placed and initial ETA shown.
  2. ETA changes or preparation/delivery delay detected.
  3. Proactive status communication sent.
  4. Order delivered late or exception escalated.
  5. Resolution, refund/credit eligibility and feedback.

Product opportunities

  • Communicate material ETA changes before users need to ask.
  • Distinguish “running late” from a known delivery blocker.
  • Make support and eligible recovery options easy to find.
  • Close the loop with a resolution status.

Prajakta’s product takeaway

When delivery slips, communication and recovery are part of the product. A reliable experience explains the delay, updates the ETA when evidence changes and offers a proportionate recovery path. Measure ETA accuracy, cancellations, support contacts and post-incident satisfaction together.
